# 架构图制作与维护

项目架构图先使用普通 SVG 确认拓扑内容，再生成手绘展示版。README 统一引用手绘 PNG，普通 SVG 和手绘 SVG 均保留在仓库中。

本规范迁自 `master` 的同名文档，保留普通 SVG、手绘 SVG 和 PNG 的分层维护方式、蓝灰配色及成图检查流程。拓扑基线对应当前分支；旧版集群与日志服务图不作为本分支的架构依据。`master` 未包含独立生成脚本，本分支提供 [render_architecture.py](../scripts/render_architecture.py) 固化转换和导出步骤。

## 修改流程

1. **修改普通 SVG。** 对照当前实现和架构设计，调整进程、service、client、共享通道及流向。分别标明当前实现和未来规划，不把规划能力画成现有组件。
2. **核对拓扑。** 导出普通图预览，检查节点数量、部署归属、连线和文字。涉及尚未决定的架构选择时，先展示源图并确认方案；明确委托生成完整版本时，完成对照核查后继续导出。
3. **生成手绘 SVG。** 脚本以固定随机种子轻微扰动轮廓和连线，保留文字、节点位置、尺寸和箭头端点，替换展示字体。
4. **导出 PNG 并检查。** 查看完整成图和 README 阅读尺寸下的效果，检查中文、文字宽度、边框及箭头。展示阶段发现内容错误时返回普通 SVG 修改。
5. **同步文档。** 更新 README 的部署说明和相关设计文档，检查状态描述和图稿一致。

## 导出工具

需要 Python 3.9 或更高版本。macOS 使用系统自带的 `qlmanage`；Linux 使用 `rsvg-convert`，并安装可用中文字体。手绘字体允许按下文约定回退，拓扑和内容保持一致。

在仓库根目录执行：

```sh
# 仅导出普通图预览，不覆盖 README 展示图。
python3 scripts/render_architecture.py --plain --output-dir /tmp/yquant-diagram-preview

# 从普通 SVG 重新生成手绘 SVG 和正式 PNG。
python3 scripts/render_architecture.py
```

脚本优先使用 `rsvg-convert`。macOS Quick Look 对横向 SVG 的缩略图可能裁切，因此先用临时方形画布渲染，再移除底部空白行，保留图内像素和原始宽高比。转换只使用 Python 标准库；图稿、字体及渲染器应在同一环境下检查。当前两张图均为横向画布。

## 拓扑基线

### 当前 monod

- 一个 `monod` 进程包含行情 service、交易 service 和一个或多个策略 service。每个策略 service 可以管理多个策略实例。
- 行情 service 经 client 向策略分发行情，策略经交易 client 提交请求并接收回报；交易 service 统一维护共享账户。
- SimNow 行情源和交易柜台位于进程边界外，分别连接行情和交易接入组件。
- 图中聚焦组件及业务连接，不展开 main 组装、container 调度、client 生命周期或进程内调用机制，不附加故障边界与示意范围的说明。

### 规划单机三种进程

- 同一主机上部署 `marketd`、`strategyd`、`tradingd` 三种进程。`strategyd` 可运行多个进程实例，共用行情和交易服务；每个进程有自己的 container 和业务线程。
- `marketd` 承载行情 service 及 server；`strategyd` 承载策略及远端 client；`tradingd` 承载交易 service 及 server。
- 图中以 `strategyd 1 … M` 表示多个策略进程，展开一个进程的内部结构；其中的策略实例用 `1 … N` 标记，区分进程数量与实例数量。
- 每个策略进程独立连接行情和交易进程。每对通信进程通过两端 message bus 连接，每个方向使用一条共享内存 SPSC 通道。合并图元表示请求和响应两个方向。
- 行情链路包含订阅请求和行情事件；交易链路包含报撤单、回报及账户更新。远端交易 client 的同步查询读取本地缓存。
- N8、N9 实现同机跨进程链路，N10 再扩展单机行情广播。此图不展开多机 relay 和运行管理组件。

## 图例与布局

| 元素 | 表达方式 |
| --- | --- |
| 主机 | 浅灰背景的虚线矩形边界 |
| 进程 | 蓝色标题栏、白色内部区域和实线边界 |
| service、client 与策略实例 | 浅蓝灰圆角矩形，归入相应进程或管理范围 |
| 接入组件、message bus | 近白圆角矩形 |
| 共享通道 | 内部带槽位的矩形缓冲区，与进程边界区分 |
| 外部系统 | 进程与主机边界外的白色圆角矩形 |
| 数据流 | 深蓝实线，单向或双向箭头标明内容流向 |

同类元素保持一致。单向行情事件使用单箭头；请求和回报合并表示时使用双箭头，并在正文说明内容。通道图元上不增加箭头，箭头落在组件端点。图中不展开对象的 C++ 所有权或完整线程实现。

当前画布：`monod` 图为 `1600 × 780`，单机多进程图为 `1600 × 1000`。文字通常为 20～30 px，标题为 34 px。调整画布时保持文字可读、连线与说明互不覆盖。

## 手绘展示规范

采用清爽的工程白板手绘风格：纯白画布、浅灰主机分区、蓝灰色图元，以及轻微不规则的笔迹。画面保持清晰的结构和文字对比度，手绘效果集中在线条与英文标签上。

### 配色与填充

配色采用 [Color Hunt 蓝灰色板](https://colorhunt.co/palette/f9f7f7dbe2ef3f72af112d4e)。语义填充色与文字颜色集中维护如下：

| 用途 | 色值 |
| --- | --- |
| 进程标题栏 | `#3F72AF` |
| 进程标题文字 | `#F9F7F7` |
| 策略实例填充 | `#DBE2EF` |
| 共享队列、交易通道与存储图元填充 | `#F9F7F7` |
| 队列内部槽位填充 | `#DBE2EF` |
| 主体文字、进程轮廓及数据流连线 | `#112D4E` |
| 主机背景 | `#F8F9FA` |
| 主机边界、系统边界 | `#868E96` |
| 次要说明 | `#64748B` |
| 画布与外部系统填充 | `#FFFFFF` |

进程标题栏使用蓝色纯色填充和近白色文字，内部保留白底；组件和共享队列分别使用表中的固定颜色。保留原始色值，通过元素之间的明暗关系区分层次。主机背景保持浅灰，进程与共享队列在主机内部清晰可辨。

画布使用纯白底，不加入纸张纹理、泛黄效果、渐变、阴影或立体效果。

### 轮廓与连线

普通 SVG 使用规整的矩形与直线。转换为手绘版时，保持图例规定的形状，在原轮廓附近加入轻微弯曲和不规则笔迹；进程仍为直角矩形，策略实例仍为圆角矩形。

以当前画布尺寸为基准，轮廓的轻微偏移约为 1～2 px，主要线宽约为 1.5～2.5 px。可叠加约 0.8～1 px 的低透明度细线形成轻微补笔，避免轮廓粗重或出现明显重影。扩大或缩小整图时，线宽与笔迹扰动按比例调整。

连线沿普通 SVG 的路径轻微扰动，保留原有转折和端点。箭头与节点的连接位置保持准确，连接汇合点与队列边缘沿用[图例与布局](#图例与布局)的箭头规则。

### 字体与文字

英文标签使用 `Chalkboard SE`，回退到 `Comic Sans MS`，呈现清晰、轻松的手写感。中文使用 `PingFang SC`、`Heiti SC` 或可用的中文无衬线字体，优先保证可读性。

按当前画布尺寸，标题约为 32 px，进程名称约为 23～27 px，策略名称约为 23～24 px，次要说明约为 16～20 px。同类文字保持一致，进程名称居中，文字与图元边缘之间保留空隙。

字体替换后重新检查文字宽度与换行。输出前确认英文和中文均完整显示，说明文字与浅灰背景之间有足够对比度。

## 可复用绘图提示词

以下提示词用于普通 SVG 内容已经确认后的手绘阶段。替换输入和输出路径后使用，配色及图例以本文件为准。

```text
请读取 docs/architecture-diagrams.md，将已确认的普通 SVG 源图
<SVG 源图路径> 转换为手绘展示版。

沿用源图的画布比例、节点数量、文字、节点位置、所属主机、连接路径和流向。
只调整视觉风格，保持源图的拓扑内容。

风格采用清爽的工程白板手绘效果：纯白画布，浅灰色主机容器，蓝灰配色，
轻微不规则的细线轮廓，清晰的手写英文标签。中文使用易读的无衬线字体。
具体色值、填充、线宽、字体和图元形状严格采用维护文档中的约定。
进程标题栏使用蓝色填充，策略实例位于对应进程内，共享通道保留槽位图例。

笔迹扰动保持轻微，保留规整的整体布局与准确的连接端点。
只在维护文档规定的端点保留箭头，汇合点不增加箭头。
不添加纸张纹理、泛黄效果、渐变、阴影、立体效果或额外装饰。

将手绘 SVG 保存为 <手绘 SVG 路径>，渲染并检查文字、边框和箭头，
再导出到 <正式 PNG 路径>。按维护文档的“成图检查”逐项核对。
如果发现拓扑内容需要调整，先回到普通 SVG 阶段修改并确认。
```

## 成图检查

- 普通 SVG 与手绘 SVG 的节点、文字、部署归属和连接关系一致。
- PNG 的宽高与源画布一致，完整展示顶部标题和底部说明，README 引用有效。
- 当前图只有一个进程；规划图包含三种进程，明确表达策略进程可部署多个实例，并标注规划状态。
- 文字不越框，连线不穿过标签，箭头不压住文字。
- 图中策略实例、各自 client 和共享账户的关系与实现或设计一致。
- 在完整图和 README 阅读尺寸下检查中文、英文及颜色对比度。
