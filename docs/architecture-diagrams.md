# 架构图制作与维护

项目架构图先使用普通 SVG 确认拓扑内容，再生成手绘展示版。项目介绍统一引用手绘 PNG，普通 SVG 和手绘 SVG 均保留在仓库中。

## 修改流程

1. **修改普通 SVG。** 根据架构变化调整进程、主机、共享队列及数据流，并同步处理单机和集群两种部署中受影响的内容。
2. **确认拓扑内容。** 渲染普通 SVG，向用户展示预览，确认节点数量、部署归属、连接方向和文字。收到修改意见后继续调整普通 SVG，等待用户确认内容后再进入手绘阶段。
3. **生成手绘 SVG。** 以确认后的普通 SVG 为依据，沿用节点位置、尺寸、文字和连线关系，只调整线条、字体及展示效果，保存到 `hand-drawn/` 下的对应文件。
4. **导出正式 PNG。** 渲染手绘 SVG 并检查成图，确认文字、边框和箭头完整，再替换正式 PNG。导出时保持画布比例，避免拉伸或裁掉图例。
5. **同步文档。** 通读项目介绍的架构章节，更新部署说明、进程职责及相关设计文档中的受影响内容。

展示阶段发现拓扑内容需要变化时，回到普通 SVG 阶段修改并重新确认。内容尚未确认时，正式 PNG 保持原版本。

## 拓扑基线

两种部署中，`tradingd` 分别连接独立的 WAL 和 MySQL 图元，二者放在 `tradingd` 所属主机内。图中表达组件关联，持久化实现机制见相应设计文档。

### 单机部署

- 一个 `marketd`、多个 `strategyd`、一个 `tradingd` 和一个 `logd` 位于同一台主机。
- `marketd` 写入共享内存广播队列，多个策略进程各自维护游标、独立消费行情。
- 每个策略通过独立的共享内存交易通道与 `tradingd` 通信；每个通道图元合并表示请求队列和回报队列。
- `tradingd` 位于策略进程右侧，交易柜台位于最右侧。
- 本机日志使用一个汇总入口，依次连接日志共享队列组、`logd` 和日志文件，省略各业务进程到队列的重复连线。

### 集群部署

- 行情主机与交易主机分别部署 `marketd` 和 `tradingd`。
- 策略主机用 `1 … N` 表示，首尾示例上下排列，中间放置竖向省略号。
- 每台策略主机包含一个中继 `marketd`、一个共享内存广播队列和多个 `strategyd`，策略进程同样用 `1 … N` 和竖向省略号表示。
- 主链路从左到右依次为行情源、行情服务、策略执行、交易服务和交易柜台。
- 跨机协议由正文说明，拓扑主图突出业务数据流。
- 日志服务在各自主机内运行；图中只在策略主机中展开本机日志链路，行情与交易主机省略同类日志组件。

## 图例与布局

| 元素 | 表达方式 |
| --- | --- |
| 系统边界 | 包围内部主机的虚线框，行情源和交易柜台位于边界之外 |
| 主机 | 浅灰背景的大矩形容器，进程放在对应主机内部 |
| 进程 | 涂色的直角实线矩形，标注 `marketd`、`strategyd`、`tradingd` 或 `logd` |
| 策略实例 | 位于 `strategyd` 内部的圆角矩形 |
| 共享队列或交易通道 | 内部带槽位的小矩形缓冲区，与进程图元区分 |
| 日志队列组 | 内部包含多行槽位的缓冲区，每行示意独立的共享内存 SPSC 通道 |
| 日志文件 | 折角文件图元，标注“日志文件” |
| WAL | 折角文件图元，标注 `WAL` |
| MySQL | 圆柱形数据库图元，标注 `MySQL` |
| 组件关联 | 普通连线，用于 `tradingd` 与 WAL、MySQL 之间的关联 |
| 数据流 | 连接线及必要的方向箭头，标注业务内容 |
| 日志链路 | 灰色虚线与必要的方向箭头，作为主业务链路下方的辅助路径 |

同类元素使用相同形状与配色。图中省略 CPU 绑定信息，进程名称居中；节点及主机边界保持足够留白。

日志队列组是多条独立队列的集合图元，每个 Logger 独占一条 SPSC 队列。`logd` 消费多个通道；日志文件在本机落盘。主业务连线保持深蓝实线，日志辅助连线使用灰色虚线，避免与交易请求和行情分发混淆。

多个同类主机或策略进程可用首尾编号 `1 … N` 和竖向省略号表示，主机编号与主机内进程编号分别使用。单机图中的交易通道编号与策略进程编号对应，通道列同步放置省略号。省略号不连接箭头。

行情分发使用单向箭头。交易请求与回报沿同一逻辑通道双向传递，箭头只放在需要表达方向的进程或外部系统端点，队列边缘与连接汇合点保持普通连线。请求与回报已经合并为一个通道图元时，文字直接标注“请求／回报／账户”。

当前画布尺寸为：单机图 `2200 × 1280`，集群图 `2100 × 1600`。节点数量变化需要扩大画布时，先确保文字可读和连线清晰，再调整尺寸。

## 手绘展示规范

采用清爽的工程白板手绘风格：纯白画布、浅灰主机分区、蓝灰色图元，以及轻微不规则的笔迹。画面保持清晰的结构和文字对比度，手绘效果集中在线条与英文标签上。

### 配色与填充

配色采用 [Color Hunt 蓝灰色板](https://colorhunt.co/palette/f9f7f7dbe2ef3f72af112d4e)。语义填充色与文字颜色集中维护如下：

| 用途 | 色值 |
| --- | --- |
| 进程填充 | `#3F72AF` |
| 进程名称及进程内说明 | `#F9F7F7` |
| 策略实例填充 | `#DBE2EF` |
| 共享队列、交易通道与存储图元填充 | `#F9F7F7` |
| 队列内部槽位填充 | `#DBE2EF` |
| 主体文字、进程轮廓及数据流连线 | `#112D4E` |
| 主机背景 | `#F8F9FA` |
| 主机边界、系统边界 | `#868E96` |
| 次要说明与日志辅助连线 | `#64748B` |
| 画布与外部系统填充 | `#FFFFFF` |

所有进程使用蓝色纯色填充，进程内文字使用近白色；策略实例和共享队列分别使用表中的固定颜色。保留原始色值，通过元素之间的明暗关系区分层次。主机背景保持浅灰，进程与共享队列在主机内部清晰可辨。

画布使用纯白底，不加入纸张纹理、泛黄效果、渐变、阴影或立体效果。

### 轮廓与连线

普通 SVG 使用规整的矩形与直线。转换为手绘版时，保持图例规定的形状，在原轮廓附近加入轻微弯曲和不规则笔迹；进程仍为直角矩形，策略实例仍为圆角矩形。

以当前画布尺寸为基准，轮廓的轻微偏移约为 1～2 px，主要线宽约为 1.5～2.5 px。可叠加约 0.8～1 px 的低透明度细线形成轻微补笔，避免轮廓粗重或出现明显重影。扩大或缩小整图时，线宽与笔迹扰动按比例调整。

连线沿普通 SVG 的路径轻微扰动，保留原有转折和端点。箭头与节点的连接位置保持准确，连接汇合点与队列边缘沿用[图例与布局](#图例与布局)的箭头规则。

### 字体与文字

英文标签使用 `Chalkboard SE`，回退到 `Comic Sans MS`，呈现清晰、轻松的手写感。中文使用 `PingFang SC`、`Heiti SC` 或可用的中文无衬线字体，优先保证可读性。

按当前画布尺寸，标题约为 32 px，进程名称约为 23～27 px，策略名称约为 23～24 px，次要说明约为 16～20 px。同类文字保持一致，进程名称居中，文字与图元边缘之间保留空隙。

字体替换后重新检查文字宽度与换行。输出前确认英文和中文均完整显示，说明文字与浅灰背景之间有足够对比度。

## 可复用绘图提示词

以下提示词用于普通 SVG 内容已经确认后的手绘阶段。替换输入和输出路径后使用，配色及图例以本文件为准。

```text
请读取 docs/architecture-diagrams.md，将已确认的普通 SVG 源图
<SVG 源图路径> 转换为手绘展示版。

沿用源图的画布比例、节点数量、文字、节点位置、所属主机、连接路径和流向。
只调整视觉风格，保持源图的拓扑内容。

风格采用清爽的工程白板手绘效果：纯白画布，浅灰色主机容器，蓝灰配色，
轻微不规则的细线轮廓，清晰的手写英文标签。中文使用易读的无衬线字体。
具体色值、填充、线宽、字体和图元形状严格采用维护文档中的约定。
进程必须涂色，策略实例位于对应策略进程内，共享队列保留槽位图例。

笔迹扰动保持轻微，保留规整的整体布局与准确的连接端点。
只在维护文档规定的端点保留箭头，汇合点不增加箭头。
不添加纸张纹理、泛黄效果、渐变、阴影、立体效果或额外装饰。

将手绘 SVG 保存为 <手绘 SVG 路径>，渲染并检查文字、边框和箭头，
再导出到 <正式 PNG 路径>。按维护文档的“成图检查”逐项核对。
如果发现拓扑内容需要调整，先回到普通 SVG 阶段修改并确认。
```

## 成图检查

- 普通 SVG 与手绘 SVG 的节点数量、文字、所属主机及连接关系一致。
- 正式 PNG 与手绘 SVG 内容一致，文档引用路径有效。
- 所有进程均有填充色，策略实例位于对应策略进程内。
- WAL 与 MySQL 是独立图元，分别直连 `tradingd`，图中保留名称与关联，不添加实现步骤。
- 单机图使用一个日志汇总入口；集群图只在策略主机展开日志服务，队列组表示各 Logger 的独立 SPSC 通道。
- 文字不越框，连线不穿过标签，箭头不覆盖边框或出现在汇合点。
- 集群图的策略主机首尾示例上下排列，主机层和进程层均有省略号，`tradingd` 和交易柜台保持在右侧。
- 检查完整图和实际阅读尺寸下的可读性，确认中文和手写英文均正常显示。
