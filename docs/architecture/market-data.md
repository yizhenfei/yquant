# YQuant 行情分发架构

YQuant 采用多进程架构。`marketd` 通过可配置的输入和输出组织行情流，`strategyd` 通过本机共享内存读取行情。

## 进程模型

| 进程 | 职责 | 部署方式 |
| --- | --- | --- |
| `marketd` | 获取行情，转换为统一事件，并向下游发布 | 单机部署一个；多机部署时，行情机器和每台策略机器各部署一个 |
| `strategyd` | 消费行情并运行策略 | 每个进程只运行一个策略，绑定一个 CPU 核心；策略增多时增加进程和策略机器 |

每台机器的共享内存由本机 `marketd` 写入，多个 `strategyd` 独立读取。

## 行情处理管线

`marketd` 的核心流程由输入、统一事件和输出构成：

```text
Source → MarketEvent → Publisher[]
```

`marketd` 负责组件生命周期和事件分发。接入和中继由配置的组件组合形成，核心流程无需区分这两种运行角色。

### 输入 Source

`Source` 负责获取数据和协议解码，产出统一的 `MarketEvent`。

| 输入类型 | 数据来源 | 处理职责 |
| --- | --- | --- |
| 交易所行情源 | 交易所、柜台或行情供应商接口 | 接收原始行情，完成协议解析和标准化 |
| 网络行情源 | 上游 `marketd` | 接收并解码内部传输格式，还原统一事件 |

### 统一事件 MarketEvent

行情在接入边界转换为统一事件，后续分发沿用这一事件语义。事件保留行情来源、源序号和源时间戳；经过中继时继续保留这些信息。源序号不可用时保留缺失标记，本机发布序号独立维护。

### 输出 Publisher

`Publisher` 接收统一事件，并按下游需要发布。一个 `marketd` 可以配置多个输出。

| 输出类型 | 下游 | 实现职责 |
| --- | --- | --- |
| 共享内存发布器 | 本机多个 `strategyd` | 更新共享内存，并封装 seqlock 读写协议 |
| 网络发布器 | 其他机器上的 `marketd` | 将统一事件编码为内部传输格式并发送 |

`strategyd` 使用统一的本机读取接口。更换网络传输实现时，保持统一事件与本机读取接口稳定。

## 部署拓扑

### 单机部署

一个 `marketd` 接入外部行情，并通过共享内存向本机多个 `strategyd` 发布。

```text
行情源 → marketd → 共享内存 + seqlock → strategyd × N
```

组件组合为交易所行情源与共享内存发布器。

### 多机部署

集群由一台行情机器和多台策略机器组成。行情机器上的 `marketd` 接入外部行情并向策略机器分发；每台策略机器上的 `marketd` 接收上游事件，再向本机多个 `strategyd` 发布。

```text
行情源 → 行情机器 marketd
             ├─ 网络 → 策略机器 A marketd → 共享内存 + seqlock → strategyd × N
             └─ 网络 → 策略机器 B marketd → 共享内存 + seqlock → strategyd × N
```

| 部署位置 | Source | Publisher |
| --- | --- | --- |
| 行情机器 | 交易所行情源 | 网络发布器；有本机策略时可同时配置共享内存发布器 |
| 策略机器 | 网络行情源 | 共享内存发布器 |

跨机按目标机器分发。同一份行情在策略机器上接收一次，再由本机共享内存提供给多个策略进程。

## 本机共享内存分发

每个共享内存发布区域保持一个写者和多个读者。单机部署时，写者是接入外部行情的 `marketd`；多机部署时，写者是本机接收上游事件的 `marketd`。同一区域的写入由单一执行流完成。

seqlock 用于校验读取一致性：读者在复制数据前后检查版本，检测到并发写入时重试。seqlock 版本号用于本机读取校验，行情源序号用于跟踪事件顺序与缺口。[机制说明](https://docs.kernel.org/locking/seqlock.html)

本机采用共享内存广播环形缓冲区，订阅端逐条消费事件。每个订阅端维护私有扫描游标，seqlock 校验槽位读取一致性。发布端保持推进，落后导致槽位被覆盖时，订阅端报告缺口并暂停后续交付，等待调用方显式恢复。

订阅端按品种和业务事件类型执行本地过滤，不匹配事件同样推进扫描游标，相关状态事件保持可见。缺口针对整个流，恢复与其他策略的正常消费隔离。组件接口、原子访问、覆盖检测和生命周期见[共享内存行情订阅发布组件](shared-memory-pubsub.md)。

## 跨机传输候选

跨机传输技术通过网络输入和网络发布器接入管线，具体选型待定。

| 技术 | 在管线中的位置 | 适用条件与取舍 |
| --- | --- | --- |
| UDP 组播 | 网络发布器和网络行情源 | 网络支持组播、多台机器订阅大量相同行情时，可减少源端重复发送；需要设计缺失检测与恢复 |
| UDP 单播 | 网络发布器和网络行情源 | 按机器聚合订阅并发送，适用于机器较少、订阅差异较大或网络不支持组播的情况 |
| [Aeron Transport](https://aeron.io/docs/) | 网络传输层 | 提供可靠 UDP 单播和组播，可评估其流控机制与本机发布层的配合 |
| RDMA | 跨机内存传输层 | 可将事件写入远端预注册的接收缓冲区，减少接收路径开销；需要支持 RDMA 的硬件与网络配置，并设计完成通知和缓冲区复用协议 |
| DPDK | 输入与网络输出的网卡收发层 | 使用用户态轮询优化收发包路径，需要预留轮询核心，并承担相应协议处理成本 |

RDMA 的可靠连接 RC 通常需要向每台目标机器分别发送；UD 支持组播，但不保证可靠交付，也不支持单边 RDMA Write。[RDMA 传输模式](https://networking-docs.nvidia.com/doca/archive/3-5-0/rdma-aware-networks-programming-guide)

RDMA 直接写入供 `strategyd` 消费的共享内存区域可作为进一步优化，需要细化其与本机唯一发布者及 seqlock 一致性协议的配合。

DPDK 可用于外部行情接入或内部 UDP 分发；也可评估 DPDK 接入与 RDMA 内部分发的组合。[DPDK 收发机制](https://doc.dpdk.org/guides/prog_guide/ethdev/ethdev.html)

## 性能评估

以行情接收至策略读到事件的端到端延迟评估分发路径，关注峰值流量下的 P99 和 P99.9，同时观察 CPU 开销、事件缺失和消费者落后情况。

策略进程绑核之外，还需评估行情收发所需核心、网卡队列与 NUMA 内存位置。比较单机策略数量增长和跨机扩展时的表现，再确定传输实现及调优参数。

## 待细化设计

- **部署参数与目标平台验证**：在实盘目标平台验证原子支持，确定容量、单事件上限及运行预算。
- **事件与传输格式**：`MarketEvent` 的类型、字段和编码方式，以及跨机传输技术。
- **上游订阅管理**：策略订阅如何聚合并传递到上游，与本地过滤配合。
- **策略状态恢复**：网络缺失、缓冲区覆盖或进程重启后，如何补齐事件或重建订单簿及策略状态。
- **输出隔离**：网络发送拥塞时，本机发布与其他下游的进度如何保持独立。
