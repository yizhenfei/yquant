# 共享内存行情订阅发布组件

`marketd` 通过共享内存广播环形缓冲区向本机多个 `strategyd` 发布行情。每个订阅端独立逐条扫描事件，使用 seqlock 验证读取一致性；落后导致事件被覆盖时报告缺口，并暂停后续交付。

组件接入 [Source 与 Publisher 行情管线](marketd.md)。单机和多机部署使用相同的本机发布协议。

## 数据语义

一个逻辑行情流对应一个共享内存区域，由一个发布端的单一执行流写入。所有订阅端共享同一份事件，每个订阅端在私有内存维护游标，发布端不等待读者。

事件保留到对应槽位被后续事件覆盖为止。在保留范围内，订阅端按本机流序号递增扫描；订阅过滤和缺口恢复分别决定哪些事件交付给策略、哪些事件被显式跳过。

三类标识分别承担不同职责：

| 标识 | 作用 |
| --- | --- |
| `generation` | 标识一次发布者实例；重启后创建新的代次 |
| `stream_seq` | 当前代次内的本机事件序号，用于读取顺序和覆盖检测 |
| 来源与源序号 | 保留上游事件身份；源序号缺失时使用不可用标记 |

本机流序号只描述本地发布，不能据此判断上游是否缺失行情。组件支持状态事件；当前 `marketd` 的输入输出使用 `QuoteTick`，检测到缺口或断流时终止管线，要求恢复后重新启动。

## 组件与接口

| 组件 | 职责 |
| --- | --- |
| `ShmSegment` | 管理共享内存映射、发现入口、实例代次与唯一发布者锁 |
| `EventCodec` | 在本地缓冲区中编码和解码固定格式事件 |
| `ShmPublisher` | 编码事件，按单写者协议提交到广播缓冲区 |
| `ShmSubscriber` | 校验槽位、维护私有游标、执行订阅过滤并报告读取状态 |

行情管线中的共享内存发布器持有 `ShmPublisher`；`strategyd` 持有 `ShmSubscriber`。

公共接口见 [shm_pubsub.h](../../include/yquant/md/shm_pubsub.h)。创建、连接和控制操作使用 `base::Status` 显式返回错误，读取结果携带状态。实现遵循项目的 C++20 与无异常约定。

| 接口 | 语义 |
| --- | --- |
| `ValidatePublishConfig(config)` | 校验端点与目标平台的完整布局，不创建文件或发布者 |
| `ShmPublisher::Create(config)` | 独占逻辑流，创建并发布新的共享内存代次 |
| `ShmPublisher::Publish(event, sequence)` | 成功时提交一个事件，并通过可选输出参数给出 `stream_seq`；失败不占用序号，错误交由输入管线处理 |
| `ShmPublisher::Tick()` | 在控制周期更新心跳，空闲时同样需要调用 |
| `ShmSubscriber::Open(endpoint, subscription, start)` | 校验并映射当前代次，建立本地订阅与游标 |
| `ShmSubscriber::TryNext(buffer, budget)` | 在预算内查找下一个匹配事件，将一致副本交付到调用方的本地缓冲区 |
| `ShmSubscriber::SetSubscription(subscription, effective_sequence)` | 替换本地过滤器，通过输出参数给出生效的扫描序号 |
| `ShmSubscriber::Resume(gap_token, sequence, position)` | 调用方处理缺口后，显式选择继续读取的位置 |
| `ShmSubscriber::Refresh(result)` | 在控制路径检查发现入口和发布端健康状态 |
| `Close()` | 释放本进程持有的资源 |

同一发布端或订阅端对象由单一执行流使用。`TryNext`、订阅变更和恢复操作串行调用。读取成功即推进扫描游标，业务处理使用返回的本地副本。

## 订阅与扫描游标

订阅条件由固定容量的品种和事件类型数组组成，每个维度最多 64 个条目。对应的 `all_instruments` 或 `all_event_types` 表示匹配全部；关闭该开关且有效条目数为零时不匹配任何值。可订阅品种由 `marketd` 输入配置决定；本组件在已经发布的行情流上执行本机过滤，上游订阅汇聚由控制层处理。

流级状态事件始终交付。品种级状态按其影响品种与订阅集合的交集交付，绕过业务 `EventType` 过滤，确保源端缺口等状态对相关策略可见。

订阅端的 `next_seq` 指向下一条待检查事件。匹配事件交付后推进游标；不匹配事件在一致性校验后同样推进游标。因此，交付给策略的序号跳跃可以来自过滤，不应直接视为行情缺失。

首次订阅默认从当前已提交尾序号的下一条开始，读取后续新事件。调用方也可以指定当前代次内的起始序号；目标已被覆盖时返回 `Gap`。订单簿初始状态由策略恢复流程准备。

订阅变更在两次读取之间生效，以当时的 `next_seq` 为边界。新增品种从该边界开始匹配，历史上已经扫描过的事件保持原处理结果。

每次读取设置两个预算：最多扫描的事件数，以及最多尝试的槽位读取次数。被过滤事件计入扫描预算，seqlock 冲突计入尝试预算，确保策略循环能够及时获得控制权。

调用方持有固定 4096 字节载荷的 `EventBuffer`，只有读取成功时更新有效长度和内容。默认起点为 `StartPosition::Live()`；指定起点可使用 `StartPosition::At(sequence)`，或同时提供预期代次以拒绝误连新实例。

## 共享内存布局

```text
SharedSegment
├─ ImmutableHeader
├─ State
├─ PublishedSequence
├─ Heartbeat
└─ Slot[capacity]
   ├─ stamp
   └─ words[word_count]
```

| 区域 | 内容与约束 |
| --- | --- |
| `ImmutableHeader` | 固定格式的引导前缀，以及事件格式版本、`generation`、容量、槽位长度、对齐值和各区域偏移；引导前缀包含 magic、布局版本、原子 ABI 和字节序；发布就绪后保持不变 |
| `State` | `Initializing`、`Ready`、`Stopped`；独立原子字段 |
| `PublishedSequence` | 最后一个完整提交的本机序号 `p`，初始值为 0；独立原子字段 |
| `Heartbeat` | 发布端在控制周期更新的本机单调时钟时间；与事件发布分开更新 |
| `Slot` | 一个事件的 seqlock 标记与定长原子载荷；运行期间不改变大小 |

头部中的可变控制字段、槽位起点与步长使用 128 字节对齐，以覆盖当前目标平台的 64 或 128 字节缓存行。共享内存对象的总长度再按系统页大小对齐，并限制在 1 GiB 以内。容量 `C` 为 2 的幂，事件序号 `s` 从 1 开始，对应槽位为 `(s - 1) & (C - 1)`。

槽位标记采用下列编码：

| `stamp` | 含义 |
| --- | --- |
| `0` | 槽位尚未使用 |
| `2 * s - 1` | 正在写入序号 `s` |
| `2 * s` | 序号 `s` 已完整提交 |

限定 `1 <= s < 2^63`，序号接近上限时切换代次，保持序号和标记不回绕。非零标记对应的事件序号为 `(stamp + 1) / 2`。

`words` 使用固定数量的 `std::atomic<std::uint64_t>` 对象。事件格式包含来源、源序号及有效标记、源时间戳、品种、事件类型、有效载荷长度和载荷内容；未使用空间在本地编码时清零。具体业务字段由带版本的 `EventCodec` 定义。

共享区只保存固定宽度字段和经过校验的偏移。跨进程地址、容器内部指针及动态对象生命周期保留在进程私有内存。单条事件必须放入一个槽位，最大载荷为 4096 字节；超过配置上限时发布失败，扩容通过新代次完成。

## 原子访问与内存序

共享标记、控制字段和载荷单元使用 `std::atomic<std::uint64_t>`，内存栅栏使用 `std::atomic_thread_fence`。编译期要求该原子类型始终 lock-free：

```cpp
static_assert(std::atomic<std::uint64_t>::is_always_lock_free);
```

支持的平台组合须明确操作系统、CPU、编译器和标准库实现，并验证同一共享对象在不同进程、不同映射地址下的原子访问行为。C++ 标准将 lock-free 操作支持跨地址访问列为推荐实践；编译期检查不能单独证明跨进程支持，目标实现须符合这一要求。[lock-free 与跨地址访问](https://eel.is/c++draft/atomics.lockfree)

原子 ABI 校验包含标准库 ABI 标识、`sizeof` 和 `alignof`，不假定原子对象与其值类型具有相同布局。发布端在 `Ready` 之前构造并初始化共享原子对象，订阅端映射后直接访问已构造对象。平台验证未通过或 ABI 不兼容时拒绝建立连接。[标准原子类型与初始化](https://eel.is/c++draft/atomics.types.generic)

订阅端采用可读写映射，API 只执行读取，映射访问方式纳入目标实现的验证范围；权限控制由部署环境保证。

共享载荷读写都以相同的 64 位原子单元进行。普通 `memcpy` 仅用于私有缓冲区；给普通共享结构加版本号并在失败后重试，仍会留下 C++ 数据竞争。[WG21 对 seqlock 数据竞争的说明](https://www.open-std.org/JTC1/SC22/WG21/docs/papers/2022/p1478r8.html)

### 发布协议

发布端先在私有缓冲区完成编码、长度检查与填充，再进入槽位提交区间：

伪代码中的 `relaxed`、`acquire` 和 `release` 分别指 `std::memory_order` 的对应值。

```text
s = next_publish_seq
slot = slots[(s - 1) & (C - 1)]

slot.stamp.store(2 * s - 1, relaxed)
std::atomic_thread_fence(std::memory_order::release)
for each fixed word i:
    slot.words[i].store(encoded[i], relaxed)
slot.stamp.store(2 * s, release)
published_seq.store(s, release)

next_publish_seq = s + 1
```

进入奇数标记之后，只执行固定次数的原子操作。该区间不分配内存、不执行 I/O 或业务回调，并保持不抛异常。源适配器的并发回调须在进入发布端之前汇入单一执行流。

### 读取协议

订阅端读取目标序号 `e = next_seq`，先以 acquire 读取 `state`，再获取 `p = published_seq.load(acquire)`。当 `e > p` 时，状态为 `Stopped` 则返回 `EndOfGeneration`，否则返回 `Empty`。先读取停止状态再读取尾序号，确保正常停止前的最终提交对读者可见。

对目标槽位执行以下协议，每次冲突均消耗尝试预算：

```text
a = slot.stamp.load(acquire)
q = (a + 1) / 2

if a != 0 and q > e:
    return Gap
if a != 2 * e:
    retry within budget

for each fixed word i:
    local[i] = slot.words[i].load(relaxed)
std::atomic_thread_fence(std::memory_order::acquire)
b = slot.stamp.load(relaxed)

if a != b:
    inspect b for overwrite, otherwise retry within budget

validate and decode local
apply subscription filter
advance next_seq
```

只有两次标记均为 `2 * e` 时，副本才可解释为事件。复制次数由连接时校验的固定布局决定，不能根据尚未校验的共享载荷长度决定访问范围。格式或长度非法时返回错误并停止交付，保持当前游标供诊断处理。

匹配事件返回本地副本，不匹配事件继续扫描。预算耗尽分别返回 `Yield` 或 `Retry`；调用方下次从尚未处理的游标继续。订阅端不向策略暴露共享槽位地址。

### 一致性依据

读者首次 acquire 读到已提交标记时，该事件的载荷写入先于本次载荷读取。如果读取期间有任意载荷单元来自后继写入，写侧 release fence 与读侧 acquire fence 通过该原子单元建立同步，使后继的奇数标记先于第二次标记读取；读者因标记不匹配而丢弃副本。两道 fence 的位置是协议的一部分。[原子 fence 规则](https://eel.is/c++draft/atomics.fences)

## 缺口检测与恢复

尾序号只能描述最后一次完整提交，覆盖检测还必须检查目标槽位。写者可能已把旧槽位置为新事件的奇数标记，却尚未更新尾序号。

例如容量为 4，已提交序号为 4，订阅端仍等待序号 1。发布端开始写序号 5 后，槽位 1 已经失效；此时 `published_seq` 仍可能为 4，订阅端必须根据槽位标记报告缺口。

当目标槽位的标记表明它正在写入或已经提交 `q > e` 时，至少区间 `[e, q - C + 1)` 已经不可读。`Gap` 返回：

- 当前 `generation`、订阅端实例身份与本次缺口的本地标识。
- 原来期望的 `expected_seq`。
- 缺失区间的已知下界，以及恢复候选 `q - C + 1`。

恢复候选表示一次观察得到的位置，恢复时仍须重新校验。写者持续推进时，新的候选也可能再次被覆盖。

订阅端进入缺口状态后暂停事件交付，保留游标。调用方完成相应策略状态恢复，再通过 `Resume` 选择从候选位置、明确指定的序号或当前尾部之后继续。重新定位返回实际生效序号；重新发现新代次会使旧缺口标识失效。

缺口针对整个本机流。已经被覆盖的内容无法再用于过滤，因此组件不能判断缺失区间是否包含所订阅品种，应由调用方保守处理。组件不因缓冲区已满而阻塞发布端，也不自动跳过缺口。

## 读取状态

| 状态 | 调用方可观察的行为 |
| --- | --- |
| `Event` | 得到一个匹配事件及其代次和本机流序号 |
| `Empty` | 当前已提交事件已扫描完，等待后续发布 |
| `Yield` | 扫描预算耗尽；可能还有未扫描事件 |
| `Retry` | 槽位写入中或校验冲突，尝试预算耗尽；游标保留 |
| `Gap` | 存在覆盖缺口；暂停交付，等待显式恢复 |
| `StreamChanged` | 控制路径发现新代次；停止旧代次交付，重新连接 |
| `EndOfGeneration` | 发布端正常停止，已提交事件已扫描完；仍可刷新发现入口 |
| `Closed` | 订阅端对象已由本进程关闭 |
| `Error` | 参数、布局、事件格式或底层操作失败，携带具体原因 |

`Refresh` 单独返回发布端健康状态。心跳超时只表示停滞，不据此认定进程死亡，也不阻止读取仍完整的已提交事件。槽位一直停留在奇数时，读取保持有界重试，由控制路径处理停滞。

控制路径发现新代次后，`StreamChanged` 优先于旧代次的缺口或结束状态。重新连接重建游标，代次之间保持明确边界。

## 创建与生命周期

POSIX 平台层封装 `shm_open` 与 `mmap`。稳定发现入口和发布者排他锁位于本机运行目录，订阅端通过逻辑流名称发现当前共享内存对象。运行目录为当前用户拥有的绝对路径，组和其他用户不可写入；组件文件与共享内存对象使用当前用户权限。

### 唯一发布者锁

每个逻辑流对应一个固定锁文件。发布端使用 `O_CREAT | O_RDWR | O_CLOEXEC` 打开文件，再调用 `flock(fd, LOCK_EX | LOCK_NB)` 获取排他锁。`EWOULDBLOCK` 表示已有发布者，通过失败 `Status` 的系统错误码报告；其他系统错误同样使创建失败。[flock 语义](https://man7.org/linux/man-pages/man2/flock.2.html)

锁描述符由发布端整个生命周期持有，退出清理完成后关闭。锁文件始终保留，固定 inode 不删除或替换。多个竞争者通过同一文件获取锁，PID 仅用于诊断。

进程异常退出后，所有相关描述符关闭时内核释放锁。组件通过 `pthread_atfork` 在子进程更新进程私有代次，发布热路径用内存比较拒绝继承自父进程的发布端。子进程释放继承对象时只关闭继承的描述符，不执行解锁或父实例资源清理，避免解除父进程的锁或删除父实例的发现入口。

### 创建与连接

创建顺序为：

1. 获取逻辑流对应的排他锁。
2. 清理上一实例的失效发现入口和 pending 创建记录，生成新的 `generation`。先记录待创建对象名称，再以唯一名称创建共享内存对象。
3. 一次性确定尺寸并映射，构造共享原子对象，初始化全部槽位和元数据，预触页并准备私有编码缓冲区。Linux 在触页前通过 `posix_fallocate` 预留后备空间，将空间不足转换为创建错误。
4. 以 release 操作发布 `Ready`，再原子替换稳定发现入口，使其指向新对象；成功后移除 pending 创建记录。

订阅端按下列顺序连接：

1. 读取发现入口，打开对象并通过 `fstat` 确认最小尺寸，按对象实际尺寸建立映射，先将访问限制在固定引导区域内。
2. 校验引导前缀的格式版本、原子 ABI 与字节序。状态原子的偏移和对齐由受支持的布局版本固定约定，通过这些检查后才允许执行共享原子操作。
3. 以 acquire 读取 `Ready`，再校验完整头部、代次、容量、槽位长度和各区域边界；检查尺寸加乘溢出、偏移范围及对齐后，才形成槽位和载荷单元的访问地址。
4. 再次核对发现入口。旧对象名称已经移除或入口发生变化时，重新发现并在预算内重试。

### 停止与重启

正常停止时，发布端完成当前事件后以 release 操作发布 `Stopped`。它在释放排他锁之前清理自身的发现入口和共享内存名称，再释放本进程映射；清理过程中保持旧映射内容，不析构或复用共享槽位。订阅端可继续读取已有映射中的完整事件。POSIX 共享内存名称移除后，已有映射可保持有效。[共享内存对象生命周期](https://man7.org/linux/man-pages/man3/shm_open.3.html)

发布端异常退出后，下一实例持锁清理上一代次的失效名称和 pending 记录，再创建新对象。pending 记录覆盖创建对象后尚未发布发现入口的中断场景。运行中的共享内存不原地截断、清零或重新初始化；旧映射维持原代次，读者通过控制周期的 `Refresh` 发现变化。固定锁文件始终保留。

### 控制周期

事件热路径只访问共享内存和私有缓冲区。调用方在控制周期调用发布端 `Tick` 与订阅端 `Refresh`；空闲期间继续更新心跳。发现入口检查、心跳更新与名称清理均在控制路径执行，重启发现延迟取决于控制周期。

## 容量与性能

配置项包括逻辑流名称、槽位容量、单事件最大字节数、扫描与尝试预算，以及控制周期和心跳停滞阈值。

容量按整个流的峰值速率与可容忍消费落后时间估算：`C >= 峰值事件速率 × 落后时间 + 突发余量`，再向上取 2 的幂。订阅端只订阅少量品种时，也按整个流评估覆盖风险。

发布端每条事件写入一次，开销不随订阅进程数量增加复制次数；每个读者仍需读取并复制一致副本。共享内存占用约为头部加 `C × 对齐后槽位大小`，每个订阅端仅维护私有游标、固定容量过滤器和本地事件缓冲区。

性能评估记录端到端 P99 和 P99.9、扫描与匹配比例、校验重试次数、覆盖缺口、CPU 开销和 NUMA 访问情况。多策略扫描全流成为瓶颈后，可按市场或品种组分流，每个流继续使用相同协议。

## 实现验收场景

| 场景 | 验收要求 |
| --- | --- |
| 单写多读 | 不同速度的多个进程独立读取，保留范围内顺序正确，发布端不等待最慢读者 |
| 并发覆盖 | 固定小容量持续覆盖，任何成功读取的事件字段均来自同一次提交 |
| 提交前覆盖 | 写者停在奇数标记、尾序号尚未前进时，旧读者仍能检测缺口 |
| 订阅过滤 | 不匹配事件推进扫描游标，过滤跳号不会误报缺口，低匹配率读取受预算限制，相关状态事件保持可见 |
| 动态订阅 | 过滤器从返回的扫描边界生效，缺口状态下变更订阅保持缺口可见 |
| 缺口恢复 | 未显式恢复时停止交付，恢复位置再次被覆盖时再次报告缺口 |
| 写者停滞 | 写者在奇数区间被抢占或退出时，读者有界返回，控制路径可观察停滞 |
| 重启与关闭 | 新旧映射不混用，旧缺口标识不能恢复新代次，正常停止后可读完保留事件 |
| 发现竞态 | 并发启动只有一个发布者成功，入口替换或旧名称移除时可重新发现 |
| 格式边界 | 拒绝不兼容布局、超长事件和非法载荷长度，验证通过前不按共享长度访问内存 |
| 原子实现 | 编译期验证标准原子类型始终 lock-free，核查目标标准库的跨进程访问、不同映射地址、ABI 和内存序；单进程数据竞争检查作为补充 |
