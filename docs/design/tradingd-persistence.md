# 交易网关持久化与恢复

`tradingd` 将交易日志写入文件映射，后台同步存储，通过检查点和日志恢复账本。当前持久化只支持股票现金账户，网关接入进程内模拟柜台；独立柜台的完整对账通过恢复组件建立账户基线，实盘 SDK 接入遵循本文的恢复契约。

交易历史查询采用独立的 [MySQL 后台入库设计](tradingd-mysql.md)，由数据库保存事件及查询投影，本地文件继续承担网关恢复。

## 写入与恢复边界

WAL 使用文件支持的 `mmap(MAP_SHARED)`。主线程写入内核管理的文件页缓存，记录完成后即可更新账本、发送请求及通知策略，逐笔不等待 `msync`、`fsync` 或设备缓存刷新。文件回写语义见 [mmap 文档](https://man7.org/linux/man-pages/man2/mmap.2.html)。

| 故障范围 | 恢复依据 |
| --- | --- |
| 正常运行 | 内存账本反映当前交易事实，后台刷盘不构成发送许可 |
| 进程崩溃，内核正常运行 | 文件页缓存仍可被读取，恢复验证完整日志，不只读取刷盘确认位置 |
| 系统崩溃或断电 | 允许尾部丢失、撕裂及乱序落盘，包括已发送、已通知的动作；独立柜台历史负责补齐 |
| 进程内模拟柜台 | 与网关一起终止，只能恢复本地有效前缀，无法独立补回已经丢失的模拟成交 |

恢复保证订单归属、成交去重和账户状态正确。缺失且没有柜台证据的本地拒单、撤单原因、通知顺序不补造。客户端不自动续接旧会话，策略回调不承诺恰好一次。

账户初始化、身份分配、客户端登记和恢复基线发布使用冷路径同步；它们在逐笔处理开始前完成。配置与启动方式见[配置与运行](#配置与运行)。

## 交易记录与应用

```text
下单：校验并预留容量 → 日志写入映射 → 提交预占 → 记录发送尝试 → 发送柜台
回报：校验与去重 → 日志写入映射 → 更新账本 → 通知策略
后台：同步已发布前缀 → 推进刷盘水位
```

`TradingEngine` 的变更钩子在全部校验通过、业务状态改变前调用。记录完整复制成功后才提交相应变更；容量及日志失败不改变新单预占、订单号、请求队列或输出。发送尝试也先记录，再调用适配器。计划提交后不再分配或重新决策；后续请求立即读取已更新的可用资金和持仓。

日志保存经过验证的事实，包含输入、预期订单及撤单号、原始单调时间和连续账本修订号。重放通过相同的确定性整数账务路径重建，核验修订号、ID、状态与容量；不匹配则阻塞，不将历史受理改判为业务拒绝。重放不调用历史柜台发送，也不重放策略回调。

网关记录同时携带客户端及本地订单归属；本地拒单单独保存结果和报告序号。模拟柜台的发送、撤单和回报也在其状态改变前记录，保存精确执行号与成交业务时间。网关和模拟器的记录可能在崩溃时相差一步，恢复通过已保存的完整模拟回报补齐账本，或结清已知未进入模拟柜台的请求。

发送返回错误、超时或缺少返回记录都不能证明柜台未收单。不自动重发旧新单，不凭发送尝试释放预占。已有柜台事实即使遇到存储故障也继续在内存入账，具体处理见[故障与容量](#故障与容量)。

## 持久身份与状态

### 身份与幂等键

| 标识 | 规则 |
| --- | --- |
| `account_key` | 绑定环境、柜台、账户、币种与账务规则；重启必须相同 |
| `ledger_id` | 初始化产生的 128 位账本身份，重启保留 |
| `run_id` | 每次启动耐久分配的新命名域，标识日志流，不复用 |
| `strategy_session_id` | 客户登记时分配，归属与标的范围在 `Welcome` 前耐久保存 |
| `generation` | 每次启动的新连接代次，只用于连接隔离 |
| 业务订单键 | `(account_key, strategy_session_id, local_order_id)` |
| 内部订单与撤单号 | 启动时耐久租用编号段，数组索引与 ID 分离，不复用丢失尾部可能使用的号 |
| 柜台委托与执行号 | 使用适配器声明的账户、市场、交易日等业务命名域；重新登录不清空去重范围 |

`IDENTITY` 原子保存命名域和 ID 分配高水位、客户归属及配置字典。新命名域同步成功前不可使用，未使用的租约也不回收。当前 `client_id` 在账本内不复用，断开和重启仍占用身份容量。

`AdapterRequestKey` 编码为 64 位命名域、8 位请求种类及 64 位域内序号，使用规范的 28 字符 Base32。外部标识缓冲上限为独立的 64 字节约束。适配器必须无损返回该键，不能截断或以散列替代。即使整笔本地订单日志丢失，也可由适配器请求键和耐久身份找到原所属策略会话。

同键同内容的成交去重，同键异内容阻塞恢复。账户修订号和客户端报告序号只在一个连接代次内单调，重启通过新代次和完整账户快照建立视图。

### 检查点覆盖内容

| 状态 | 保存内容 |
| --- | --- |
| 元数据 | 版本、账本和运行身份、覆盖 LSN、后续段与偏移、捕获时间 |
| 账本 | 资金、持仓、逐订单预占、订单、成交去重、请求和本地更新队列、编号高水位 |
| 网关 | 客户身份、本地订单映射、拒单、报告序号和撤单关联 |
| 模拟柜台 | 订单阶段、执行号、完整回报历史、计划及剩余等待时间 |

显式编码业务字段，不保存 C++ 布局、指针、哈希桶或文件描述符。恢复重建索引和队列，验证成交累计量、现金及逐订单预占总和。总持仓、可卖、预占与不可卖部分分开保留，重启不会把当日买入持仓变成可卖。

已有账本不读取配置的初始资金或持仓覆盖恢复结果。账户键、完整标的定义及模拟规则必须兼容；类型、价位和数量步长的变化均拒绝恢复。适配器恢复使用检查点内的初始模拟账户。套接字与单调时钟期限重新建立，历史单调时间不与新进程时钟直接比较。

## 文件映射与后台同步

### 目录与生命周期

```text
state_directory/
  LOCK
  IDENTITY
  CURRENT
  snapshot-<run_id>-<lsn>.bin
  stream-<run_id>/
    segment-<sequence>.wal
```

实际运行号和段号采用补零十进制文件名。进程从读取状态到收尾始终持有稳定 `LOCK` 的排他 `flock`，不删除锁文件。首版使用本地文件系统；该锁不能隔离另一台机器的旧柜台会话。

`CURRENT` 是带校验的快照指针，绑定运行、LSN 及续扫游标。控制文件、快照和段头均带格式、长度和校验。初始化必须显式执行，已有状态、初始化残留、未知版本或身份不匹配均不自动变成空账户。

后台创建并物理预分配备用段，`ftruncate` 到固定段长，建立 `MAP_SHARED` 映射并逐页写触，写入和同步不可变段头及目录项。主线程只切换就绪映射，不创建、扩展或同步文件。

每条事务不跨段，准入始终预留 `SegmentEnd` 封口空间。段不足时发布封口后切段，不等待刷盘。封口保存下一段及末 LSN，不消耗业务 LSN；恢复只通过有效封口续扫，不将预分配零区解释为日志。后台同步封口后才解除旧映射，存储文件保留。

预触页减少缺页抖动；映射仍可能遇到写页准备和脏页节流，尾延迟需测量。`MAP_POPULATE` 不能替代实际预热，见 [mmap 文档](https://man7.org/linux/man-pages/man2/mmap.2.html)。

### 完整记录与刷盘水位

记录包含长度、类型、版本、运行身份、连续 LSN、载荷、CRC32C 和最终发布标记。发布字段对齐，使用 release/acquire；CPU 发布不等于存储顺序，断电后仍须验证正文和校验。

`published_lsn` 表示已完成映射写入，`durable_lsn` 表示后台已成功同步的连续前缀。后台捕获前缀，对所有前序段及目标段执行页对齐 `msync(MS_SYNC)` 和平台文件同步，成功后确认水位；不能越过前段同步错误。页面可能顺带刷出后续字节，不能因此扩大确认范围。

默认达到 1 MiB 或 10 ms 时触发同步，以先发生者为准。调度周期不是数据丢失窗口上限。现代 Linux 的 `MS_ASYNC` 不提供所需完成确认，见 [msync 文档](https://man7.org/linux/man-pages/man2/msync.2.html)。Linux 使用 `fsync` 并在文件创建、重命名时同步目录，见 [fsync 文档](https://man7.org/linux/man-pages/man2/fsync.2.html)；macOS 还使用 `F_FULLFSYNC` 请求刷新设备缓存，见 [Apple 文档](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html)。等待发生在后台或冷路径。

## 检查点与重启

检查点在完整业务边界捕获账本、网关和模拟器，记录精确续扫游标。主线程编码到初始化时分配的固定缓冲，随后立即继续交易；后台只读该不可变缓冲。

发布顺序为：写快照临时文件 → 同步 → 原子改名并同步目录 → 写并同步新 `CURRENT`。不要求 WAL 先同步到快照位置，快照本身完整覆盖已捕获状态。一次一个任务，完成前不复用缓冲；身份写入与检查点控制文件写入串行。关闭先完成任务并加入线程，再释放映射。

重启先取得锁并验证 `IDENTITY`、`CURRENT` 和快照，从记录的段与偏移续扫。快照覆盖之前的日志不参与恢复。遇未封口零尾、半条记录、CRC 错误或连续性缺口时停在首个无效位置，不跳过坏记录；控制元数据或锚点段头损坏阻塞启动。

当前模拟模式的恢复过程：

1. 装载检查点，重放有效日志，重建归属及去重。
2. 耐久分配新运行与 ID 租约，丢弃历史待发送队列，不重发旧新单；补齐模拟器已经保存但账本尚未应用的回报。
3. 对模拟器中没有对应请求的本地未决单作明确的模拟拒绝；处理已登记但未送达模拟器的撤单，撤销旧策略活动单并结清回报。
4. 重新定位模拟计划期限，所有新接收时间使用当前单调时钟，不补造停机期间成交。
5. 创建新日志流并耐久发布完整恢复基线后再开放监听；旧策略身份继续保留。

恢复期间采用模拟调度快速推进已有计划并完成撤单，成交与撤单仍可竞争。它不向旧策略发送回调。正常停止要求订单和回报排空，再等待最终日志同步及检查点；超时不将未知订单伪装为已撤销。

## 独立柜台对账契约

`BuildRecoveredBrokerState` 接受柜台的完整历史和一致性账户快照，即使本地没有对应订单记录，也通过稳定请求键恢复归属。输入须满足：

- 旧发送者已被隔离，历史查询覆盖上次完整对账边界，包含所有活动单及区间内终态单。
- 订单、逐笔成交和账户都对应同一个明确的柜台边界；每个返回订单带完整累计成交明细。
- 历史分页、实时衔接及终态查询均完成。空页或查询超时不能证明订单不存在。
- 柜台字段已规范化为账本单位，区分余额与可用、总持仓与可卖、冻结与本地预占。

恢复组件验证覆盖、字典、业务身份、内容冲突及累计量，输出新的账户基线和去重事实。旧活动单还须执行风险减少撤单并重新取得最终边界。`TradingEngine::RestoreReconciled` 安装已排空订单、完整成交及账户基线，历史成交不再次扣减该余额或持仓。

基线耐久发布期间，边界之后的回报必须保存在有界缓冲；发布后按连续游标去重、追加新 WAL 并应用，再开放交易。缓冲溢出、查询缺口、无法归属、冲突或差异未解决均保持关闸。实盘 SDK 的查询、发送者隔离及回报衔接由相应适配器提供，当前网关未配置实盘适配器。

## 故障与容量

追加及轮转不使用 C++ 堆、互斥锁或文件系统调用。账本、请求、回报、客户端和映射段均有上限；后台无法补足就绪段时返回容量错误，主线程不临时建文件。

存储失败后停止新单和新风险发送，保留订单与预占，继续处理真实成交及必要撤单。无法完整记录的范围标为故障，不再发布普通检查点掩盖缺口，收尾后以失败退出。映射发生不可恢复访问故障时进程终止，由重启恢复处理。

身份、订单和成交容量跨重启保留，不因快照获得新额度。当前保留历史段及快照，不自动清理、日切或封存；部署需预留磁盘并安排离线维护。自动归档和世代切换属于后续维护接口，不能通过删除状态目录或恢复初始配置来重置账户。

## 内部接口

```cpp
Status Journal::Acquire(const JournalOptions&) noexcept;
Status Journal::TryAppend(uint16_t type, span<const byte> payload,
                          uint64_t& lsn) noexcept;
JournalCursor Journal::GetCursor() const noexcept;
Status Journal::ReplayFrom(const JournalCursor&, Callback, void*, Result&) noexcept;
Status Journal::Flush() noexcept;  // 冷路径

Status TradingMutationSink::BeforeCommit(const TradingMutation&) noexcept;
Status TradingEngine::ExportCheckpoint(span<byte>, size_t&) const noexcept;
Status TradingEngine::RestoreCheckpoint(span<const byte>) noexcept;
Status TradingEngine::ReplayMutation(const TradingMutation&, Dispatch*) noexcept;
Status TradingEngine::RestoreReconciled(const AccountSnapshot&,
    span<const OrderSnapshot>, span<const Fill>) noexcept;
```

写入成功仅表示映射记录完成；刷盘水位不授予逐笔发送许可。期货持久化入口显式返回不支持，独立策略宿主的期货模拟保留原行为。变更钩子借用输入直到返回，调用方先完成有界复制，不能保留随后复用的计划地址。恢复及编解码失败保留调用方输出，初始化中途失败丢弃候选网关。

## 配置与运行

默认配置保留内存模式。启用示例见 [persistent.json](../../examples/tradingd/persistent.json)：

```json
{
  "persistence": {
    "directory": "state/account-A",
    "account_key": "simulation/account-A/CNY",
    "wal_segment_bytes": 67108864,
    "reserve_segments": 2,
    "sync_interval_ms": 10,
    "sync_after_bytes": 1048576,
    "snapshot_interval_ms": 60000
  }
}
```

目录相对网关配置文件解析。首次运行显式初始化，已有状态启动时省略该标志：

```sh
yquant-tradingd --config persistent.json --initialize-state
yquant-tradingd --config persistent.json
```

`--check-config` 只验证，不创建状态目录。初始化拒绝覆盖已有文件；缺失控制文件的普通启动失败。

| 参数 | 约束 |
| --- | --- |
| WAL 段 | 默认 64 MiB；4 MiB 至 1 GiB，2 的幂 |
| 备用段 | 默认 2；范围 2 至 16，启动还准备一个活动段 |
| 同步周期 | 默认 10 ms；1 至 1000 ms |
| 同步字节阈值 | 默认 1 MiB；4 KiB 至单段容量 |
| 检查点间隔 | 默认 60000 ms；1000 至 3600000 ms |
| 单条载荷 | 16 KiB；编码、复制和校验使用同一具名上限 |
| 检查点镜像 | 64 MiB；独立于段容量，文件读取先验证声明长度 |

## 验证

组件及集成测试覆盖：

- 正常轮转、封口、预分配零尾、半条记录、CRC 错误、缺段及快照游标续扫。
- 后台同步被暂停时仍可追加，映射耗尽时有界失败，追加与轮转的主线程无 C++ 堆活动。
- 提交前日志失败保留预占、队列、编号和成交；账本与模拟器状态编解码失败不部分提交。
- SIGKILL 后从文件页缓存恢复资金持仓；逐个截断下单、发送和撤单记录后不重发旧新单。
- 周期检查点与后续 WAL 衔接、正常排空及最终同步、身份防复用、重复实例和控制文件损坏。
- 独立柜台完整历史恢复缺失终态单、成交去重、账户基线不重复扣款，以及查询不完整时拒绝开闸。

进程崩溃测试不替代真实断电验收。部署性能需测接收至柜台发送、回报至策略通知的 P50/P99/P99.9，以及缺页、脏页节流、同步延迟和检查点编码暂停。
