# SPSC 队列设计

更新日期：2026-10-15。

`SpscQueue` 的核心目标是提供低延迟的内存消息队列。它采用单生产者、单消费者模型，按帧传递字节载荷，提供零拷贝写入和读取能力。组件位于 `yquant_base` 静态库中。

目标平台见 [README](../../README.md#目标平台)。

## 设计目标

| 目标 | 设计机制 |
| --- | --- |
| 无锁 | 两端分别维护自己的游标，通过无锁原子操作发布状态，不使用互斥锁或 CAS 重试循环 |
| 非阻塞 | 空间不足、没有已发布帧或本端已有借用时立即返回，不等待另一端推进 |
| 零拷贝 | 帧头与载荷物理连续，借出单个 span 供调用者直接访问，队列不搬运载荷 |

队列基于外部提供的连续定长内存运行，初始化算法与存储生命周期分离。队列只处理字节，不解释业务内容，不构造或析构用户对象。

## 对外接口

视图和借用句柄仅包含固定大小的本地状态，不分配堆内存。

### 布局与绑定

```text
RequiredBytes(capacity) -> SizeResult{status, bytes}
Initialize(memory, capacity) -> status
view.Attach(memory, role) -> status
view.Detach() -> status
```

`required_alignment()` 返回 128 字节。`RequiredBytes(capacity)` 校验容量并计算控制区和数据区的总字节数，检查整数溢出；失败时 `bytes = 0`。

`Initialize(memory, capacity)` 只在外部区域建立布局，不自动绑定视图，也不取得存储所有权。`Attach(memory, role)` 校验已有布局，再为当前对象绑定生产端或消费端角色；不修改共享状态。

布局接口通过 `SpscStatus` 返回失败原因：

| 状态 | 含义 |
| --- | --- |
| `kInvalidArgument` | 容量非法、总长度溢出、空基址或绑定角色不是生产端或消费端 |
| `kInsufficientStorage` | 提供的区域不足以覆盖控制区或完整布局 |
| `kMisalignedStorage` | 区域基址不满足对齐要求 |
| `kUnsupportedPlatform` | 平台不满足 64 位无锁原子及布局要求 |
| `kIncompatibleLayout` | 既有标识、版本、ABI、偏移或容量元数据不兼容 |

新建视图处于未绑定状态，`attached() == false`、`role() == kUnbound`，容量访问器均返回零。`Attach` 只允许未绑定视图；对已绑定对象调用返回 `kInvalidState`。失败不改变本地绑定状态。

`Detach()` 只解除本地绑定，不修改游标、控制对象或外部内存。有借用时返回 `kBusy` 并保留绑定；已经未绑定时返回 `kSuccess`。重新绑定前先结束借用并解绑。

生产端视图只能调用 `CheckWrite`、`TryReserve` 和 `TryWrite`，消费端视图只能调用 `TryAcquire` 和 `TryRead`。未绑定或角色错误返回 `kInvalidState`，不访问共享游标。角色不匹配的检查先于借用冲突检查。

`capacity()` 返回包含数据帧头与尾部 padding 占用空间的数据区总字节容量；`max_payload_size()` 返回单帧载荷的长度上限。已绑定视图的这些访问器只读取本地缓存的不可变信息。

### 零拷贝帧接口

```text
producer.TryReserve(n) -> ReserveResult{status, reservation}
reservation.payload() -> span<byte>
reservation.Commit(m) -> status
reservation.Cancel()
consumer.TryAcquire() -> AcquireResult{status, lease}
lease.payload() -> span<const byte>
lease.Release() -> status
lease.Cancel()
```

`TryReserve(n)` 预留最多 `n` 字节载荷，成功结果的 `reservation` 持有写借用；`payload()` 返回长度为 `n` 的连续可写 span。`Commit(m)` 发布其前 `m` 字节并结束借用，`Cancel()` 取消借用且不发布数据帧。

`TryAcquire()` 成功结果的 `lease` 持有下一帧读借用；`payload()` 返回完整载荷的连续只读 span，`size()` 返回载荷长度。`Release()` 消费整帧并结束借用，`Cancel()` 结束借用但保留队头数据帧。

`ReserveResult` 和 `AcquireResult` 成功时的句柄 `active() == true`，失败时句柄不活动。空载荷仍对应有效借用；不能用 span 是否为空判断借用是否存在。

数据帧的帧头和载荷必须一起放在同一物理连续区间。尾部不足时跳过剩余尾段，在数据区起点预留整帧，不拆成两段，也不拼接临时缓冲。空载荷仍须提交和释放对应帧。

完成绑定和角色检查后，`TryReserve` 和 `CheckWrite` 返回 `kSuccess`、`kFull`、`kTooLarge`、`kBusy` 或 `kCorrupt`；`TryAcquire` 返回 `kSuccess`、`kEmpty`、`kBusy` 或 `kCorrupt`。失败不创建借用。

`CheckWrite(n)` 仅检查总空闲字节能否容纳 `H + n`，不计跳尾所需 padding。成功不保证连续空间足够；真实预留仍需调用 `TryReserve`，由它推进必要的回绕处理。

padding 是内部控制数据，不返回调用者。预留返回 `kFull` 或取消写借用时可能已发布 padding；读取返回 `kEmpty`、输出不足或取消读借用时可能已回收 padding。这些操作不发布或消费失败的业务帧，不回滚已经完成的内部回绕。

提交长度超过预留长度时返回 `kInvalidSize`，不发布且保留借用，调用者可修正或取消。已结束句柄的 `Commit` 或 `Release` 返回 `kInvalidState`；`Cancel` 为空操作，`payload()` 返回空 span，读句柄的 `size()` 返回零。

接口使用 `SpscStatus` 表达失败，不使用异常。运行期接口为 `noexcept`，不分配堆内存、不记录日志、不调用业务回调。

### 复制便利接口

```text
producer.TryWrite(payload) -> status
consumer.TryRead(output) -> ReadResult{status, payload_size}
```

`TryWrite(payload)` 预留后复制输入载荷并提交一帧，状态沿用写预留结果。`TryRead(output)` 借用下一帧，复制完整载荷到输出区，再释放该帧。复制接口的输入、输出区不得与当前队列存储重叠。

`TryRead` 的输出 span 表示容量，结果包含 `status` 和 `payload_size`：

| 状态 | 结果含义 | 队列与输出区 |
| --- | --- | --- |
| `kSuccess` | 返回实际载荷长度，可以为零 | 消费整帧，只修改输出区前 `payload_size` 字节 |
| `kEmpty` | 没有可读数据帧，长度为零 | 可能回收 padding，输出不变 |
| `kBufferTooSmall` | 返回下一帧所需载荷容量 | 取消读借用，保留数据帧及输出；可能已回收 padding |
| `kInvalidState` | 未绑定或不是消费端，长度为零 | 不访问共享游标，输出不变 |
| `kBusy` | 当前消费端视图已有借用，长度为零 | 不改变已有借用或输出 |
| `kCorrupt` | 状态或帧编码不合法，长度为零 | 不消费数据帧、不修改输出；可能已回收前置 padding |

输出区大于队列容量仍可读取一帧，空输出区可以接收空帧。成功读取空帧与空队列通过状态区分，接口不拆分一帧或合并多帧。

## 借用与所有权

### 写入借用

预留过程可以先发布尾部 padding，再在选定的连续位置建立写借用。借用记录该数据帧的起点和预留长度，数据帧仍未发布；调用者提交前必须填好实际发布前缀的全部字节。

`Commit(m)` 允许 `0 <= m <= reserved_size`，从选定的帧起点发布前 `m` 字节。较短提交按实际帧长推进，剩余预留字节可供后续使用，已发布的尾部 padding 保留。取消不发布数据帧，也不回滚 padding 或调用者已改写的空闲字节。

### 读取借用

定位时可以先回收前置 padding；取得数据帧借用后不推进该帧的读游标，生产端仍将整帧视为占用。调用者完成全部载荷访问后才调用 `Release`；异步 I/O 引用该内存时，须等操作完成后再释放。

取消读借用不消费数据帧，下次取得的仍是同一队头数据帧，已经回收的 padding 不恢复。取消或释放后，先前取得的只读 span 均失效。

### 句柄生命周期

视图和借用句柄的构造、析构，以及借用句柄的移动均为 `noexcept`。新建借用句柄不活动。

借用句柄固定大小、不可复制、可以移动，不分配堆内存。移动转移借用并使源句柄不活动；移动赋值先取消目标原有借用，自移动赋值不做操作。移动前取得的 span 仍随转移后的借用有效。句柄析构取消尚未结束的借用：写句柄不隐式提交，读句柄不隐式消费。提交、释放或取消后，该借用取得的全部 span 失效。

队列视图不可复制或移动，保证句柄所引用的视图地址稳定。每端同时最多一笔借用；借用期间当前端点视图上的同角色操作返回 `kBusy`，另一端可以继续运行。不得通过其他视图绕过同端借用。

队列视图及外部存储必须比借用活得更久。角色移交、解绑、重新初始化或回收区域前，先结束相关借用。视图析构发现仍有借用时终止进程，开发构建同时提供断言诊断。视图析构不销毁共享控制对象或回收底层存储。

## 外部内存与布局

### 内存提供方

调用者提供可读写、连续、固定大小且基址对齐的区域，可来自初始化阶段申请的动态内存、静态存储或共享内存映射。

队列只保存本进程视图与端内借用状态，不申请、扩容、释放、映射或解除映射存储。视图销毁不销毁共享控制状态，提供方保持区域有效直到全部访问结束。

### 共享布局

布局版本为 `3`，包含连续数据帧和尾部 padding 的编码规则。固定使用 `A = 128` 字节对齐，不可变元数据、写游标和读游标各占一个独立的 `A` 字节区域，数据区从 `3 × A` 开始。

| 区域 | 相对基址的偏移 | 内容 |
| --- | --- | --- |
| 布局元数据 | `0` | 标识、布局版本、ABI 标识、数据偏移、数据容量 |
| 生产端状态 | `A` | `atomic<uint64_t> write_pos` 与填充 |
| 消费端状态 | `2 × A` | `atomic<uint64_t> read_pos` 与填充 |
| 帧数据区 | `3 × A` | `capacity` 字节的帧编码存储 |

借用句柄、span、端内标记和进程地址不进入共享区域。每端持有自己的本地视图，用基址加固定偏移访问相同状态。

ABI 标识覆盖本机字节序、机器字长、原子对象的大小和对齐，以及编译器、标准库版本。接入时要求标识匹配。

容量 `C` 为二的幂，满足 `4 <= C < 2^63`；总长度 `3 × A + C` 须可由 `size_t` 表示且不超过区域长度。元数据和原子类型的大小、对齐须满足各自区域要求；改变共享布局、帧头或对齐要求时升级版本。

生产端预留和消费端取帧都需要计算环内位置，属于逐帧执行的热路径。二幂容量使索引可直接用 `position & (C - 1)` 计算，避免运行时整数除法；同时 `C` 整除 `2^64`，保证 `uint64_t` 累计游标自然回绕后，物理索引仍按环形位置连续变化。

### 并发角色

全局只有一个串行生产端和一个串行消费端，两端可同时运行。端内排他覆盖整个借用期，多个视图不增加角色数；线程间移交角色前结束借用，由调用者同步前后状态。

未提交的数据帧对消费端不可见，消费端可以返回 `kEmpty`，但能够先回收已发布的 padding；未释放读取仍占空间，生产端可以返回 `kFull`。这些状态直接返回，不等待对端提交或释放。[环形缓冲区的并发角色与容量观察](https://www.kernel.org/doc/html/latest/core-api/circular-buffers.html)

## 初始化与接入

### 初始化

`Initialize` 只在独占区域时执行：

1. 校验容量、总长度计算、基址对齐、区域大小和原子平台支持，失败时不修改区域。
2. 就地建立元数据和原子游标，设置 `write_pos = read_pos = 0`。
3. 数据区不需清零，零游标表示尚无已发布帧。
4. 由调用者通过区域外的线程或进程同步机制通知其他使用方初始化完成。

初始化不管理存储生命周期。重新初始化前须停止两端、结束借用和旧视图使用，运行中不复位游标。

原子初始化本身不是原子操作，其他端不能与控制头构造并发访问，也不能轮询尚未构造的区域内标志来协调构造。[原子对象初始化规定](https://eel.is/c++draft/atomics.types.operations)

### 接入与回收

生产端和消费端各建立独立本地视图，分别调用 `Attach(memory, Role::kProducer)` 和 `Attach(memory, Role::kConsumer)`。角色只约束本地接口，不在共享区域注册，也不检测其他视图是否已占用同一角色。

`Attach` 的前提是初始化完成并对接入方可见。它先检查基址对齐和区域至少覆盖固定控制区，再读取不可变元数据，校验标识、版本、ABI、偏移、容量及总边界，最后建立本地视图。不清零、不重新构造原子对象、不重置游标。

接入不把独立读取的游标差当作一致快照。`Detach` 结束本地绑定，不能用于通知或等待另一端停止。各端结束借用和视图使用后，由提供方回收或解除映射区域；销毁一个视图不代表另一端已停止。队列不自动接管失效进程。

## 连续帧与尾部回绕

### 数据帧与回绕标记

```text
uint32_le payload_size | payload[payload_size]
```

帧头固定 `H = 4` 字节，由队列按小端编码和解码。长度值 `UINT32_MAX` 保留为回绕标记，普通数据帧的帧头和载荷整体连续，不跨越物理尾部。

```text
max_payload = min(C - H, UINT32_MAX - 1)
frame_bytes = H + payload_size
```

令当前位置的尾部长度为 `tail = C - (position & (C - 1))`。需要回绕时，整个 `tail` 字节作为 padding：

- `tail >= H`：在尾段起点写入回绕标记，其余尾字节不解释、不必清零。
- `tail < H`：不写不足长度的帧头，由消费端按尾部长度识别隐式 padding。

padding 占用队列容量，必须通过写游标发布、通过读游标回收。标记不能位于数据区起点，padding 不作为数据帧返回。

### 游标与容量

```text
used  = uint64_t(write_pos - read_pos)
free  = C - used
index = position & (C - 1)
```

两个游标为累计编码字节位置，包含数据帧与 padding，以 `uint64_t` 按模 `2^64` 回绕，分别只由生产端和消费端更新。有效状态保持 `0 <= used <= C`，未消费区域由完整数据帧和至多一段尾部 padding 组成。

未提交的数据帧预留不计入 `used`，由单写借用约束保护；未释放的数据帧仍计入 `used`。总空闲字节足够时，也可能因连续空间和跳尾开销不足而返回 `kFull`。

所有长度加法先转为 `uint64_t`，范围确认后再转本地长度类型；不用有符号游标比较。空载荷占 `H` 字节，`C == H` 时支持一帧空载荷。

## 零拷贝写入算法

### 连续区域预留

`TryReserve(n)` 在已绑定生产端视图上执行；未绑定或角色错误返回 `kInvalidState`：

1. 当前生产端视图已有借用时返回 `kBusy`；`n > max_payload_size()` 返回 `kTooLarge`。
2. 读取 `w = write_pos.load(relaxed)`、`r = read_pos.load(acquire)`，计算 `used = uint64_t(w - r)`；`used > C` 返回 `kCorrupt`。
3. 计算 `free = C - used`、`F = uint64_t(H) + n`、`tail = C - (w & (C - 1))`。
4. 若 `F > tail`，先判断 `tail <= free`；不足则返回 `kFull`。足够时按显式或隐式规则建立 padding，执行 `write_pos.store(w + tail, release)`，然后令本地 `w += tail`、`free -= tail`。
5. 若 `F > free`，返回 `kFull`。此前已发布的 padding 保留，本次不建立数据帧借用。
6. 本地记录数据帧起点 `w`、预留长度 `n` 和借用标记，返回从数据区 `w & (C - 1)` 后 `H` 字节开始的单个连续可写 span。

返回 `kFull` 不等待消费端回收 padding，后续调用重新观察读游标。成功预留不写数据帧头、不初始化或搬运载荷。

`CheckWrite(n)` 先校验绑定和生产端角色，再依次校验借用状态、长度和占用量合法性，最后只比较所需帧长与总空闲字节，不判断 `tail + F`、不发布 padding。它是粗预检，不能替代真实预留。

### 提交与取消

`Commit(m)` 验证句柄有效和 `m <= n`，非法长度保留借用。有效提交中，调用者已填好前 `m` 字节：

1. 在所选连续帧起点 `w` 编码长度 `m`。
2. 执行 `write_pos.store(w + H + m, release)`，一次发布完整数据帧。
3. 清除借用状态，使写 span 失效。

短提交沿用预留时选定的帧位置，不移动载荷。取消只清除数据帧借用，不推进数据帧游标，不撤销已经发布的 padding。

### 空队列的回绕进度

例如 `C = 16`、`w = r = 12`，预留 12 字节载荷需要 16 字节整帧。尾部仅剩 4 字节，先发布这 4 字节 padding，再返回 `kFull`。消费端回收 padding 后可返回 `kEmpty`，此时两游标均位于环首，生产端后续可预留整帧。

独立发布 padding 避免空队列停在非零位置时，大帧持续失败。进度依赖消费端继续调用，写入端不自行等待或修改读游标。

## 零拷贝读取算法

### 定位连续数据帧

`TryAcquire()` 在已绑定消费端视图上执行；未绑定或角色错误返回 `kInvalidState`：

1. 当前消费端视图已有借用时返回 `kBusy`。
2. 读取 `r = read_pos.load(relaxed)`、`w = write_pos.load(acquire)`，计算 `used = uint64_t(w - r)`；`used > C` 返回 `kCorrupt`，`used == 0` 返回 `kEmpty`。
3. 计算 `offset = r & (C - 1)`、`tail = C - offset`。若 `tail < H`，当前位置只能是隐式 padding，要求 `used >= tail`；否则要求 `used >= H` 后读取连续长度头，遇到回绕标记时要求 `offset != 0` 且 `used >= tail`。
4. 发现合法 padding 时，执行 `read_pos.store(r + tail, release)` 回收整段，令本地 `r += tail`、`offset = 0`、`tail = C`，再 acquire 读取一次写游标并重算占用；非法占用返回 `kCorrupt`，没有后继数据时返回 `kEmpty`。
5. 非空但 `used < H` 时返回 `kCorrupt`，否则在当前数据帧起点解码长度。若是非法回绕标记、载荷长度超过上限、帧长超过该处尾部连续长度或超过已发布字节数，返回 `kCorrupt`。
6. 记录数据帧起点 `r`、帧长及本地借用标记，不推进该数据帧的读游标，返回连续只读载荷 span。

单次取得最多处理一段 padding，再检查一个数据帧，不使用扫描或等待循环。padding 回收后物理位置为零，不能出现第二个合法回绕标记。

### 释放与取消

所有载荷访问结束后，`Release()` 执行 `read_pos.store(r + H + payload_size, release)`，消费整帧并使 span 失效。取消不消费数据帧，下次仍可取得同一帧；已经回收的 padding 不恢复。

损坏返回不创建借用或消费损坏数据帧，但此前可能已回收合法 padding。调用者停用队列，两端停止后处理，不猜测新的帧边界。

## 复制便利接口算法

`TryWrite(payload)` 预留连续载荷区域，执行一次载荷复制，再按原长度提交。`TryRead(dst)` 先取得连续数据帧，输出不足时取消借用并返回所需容量；容量足够时执行一次复制，再释放整帧。

便利接口在载荷复制前完成失败检查，失败不发布或消费数据帧，但可能已处理 padding。已有借用返回 `kBusy`，不改变原借用；空帧仍经过完整借用协议。

## 发布顺序与进度

调用者先完成载荷写入，队列再编码头部并 release 发布写游标；消费端 acquire 观察后才能取得和访问该帧。消费端完成全部读取后 release 发布读游标；生产端 acquire 观察后才能复用空间。[C++ 原子内存顺序](https://eel.is/c++draft/atomics.order)

padding 标记先写完再 release 发布，消费端完成标记访问后 release 回收尾段；数据帧沿用相同的发布与复用关系。

零拷贝控制路径最多处理一次尾部跳过、固定大小的帧头和单个连续 span，步骤数量不随载荷长度增长。调用者承担载荷访问与 I/O 耗时，复制便利接口的复制成本随载荷长度增长。

所有 `Try*` 接口只检查当前状态，不使用互斥锁、CAS 重试或等待循环。平台须提供始终无锁的 64 位原子操作，不回退到隐藏锁。

## 共享内存使用契约

共享区域使用相对偏移，各端采用匹配的布局版本、CPU 字节序、工具链和原子 ABI。借用 span 仅为本进程地址，不写入共享布局、不跨进程传递，各进程从自己的映射建立视图。

跨进程运行要求原子操作不依赖进程私有状态，能在同一物理位置的不同地址间正确通信。目标平台须验证该能力，`is_always_lock_free` 不能单独证明任意平台的跨进程支持。[无锁原子的地址独立性](https://eel.is/c++draft/atomics.lockfree)

`Attach` 不重建控制状态。共享内存创建、权限、映射、初始化通知和最终回收属于外部资源层。

## 日志模块接入

当前日志路径保留 Logger 格式化缓冲和后台批缓冲，使用 `TryWrite`、`TryRead` 复制便利接口。两次载荷复制分别发生在 Logger 缓冲到队列、队列到后台批缓冲，所有权与复用规则见[日志选型与设计](logging.md)。

直接使用零拷贝接口的调用者在预留区域生成载荷，从读借用中处理载荷，并在处理完成后归还空间。

## 验证标准

| 场景 | 验收条件 |
| --- | --- |
| 目标与接口 | 零拷贝控制路径无载荷复制或堆分配；满、空、借用冲突立即返回 |
| 借用发布 | 未提交写入不可读，未释放读取不可覆盖，两个端可并行持有借用 |
| 长度与取消 | 短提交沿用所选连续位置，剩余预留可复用；取消保留业务帧语义，不回滚已处理 padding；非法提交保留借用 |
| 视图与句柄生命周期 | 视图不可复制或移动；句柄移动转移借用，析构取消；结束后 span 失效；重复提交或释放不推进游标 |
| 帧边界 | 帧头与载荷整体连续，span 不越物理尾部；空帧占 4 字节，与空队列区分 |
| 尾部回绕 | 恰好填尾不添加 padding；尾剩 1 至 3 字节隐式跳过，其余不足尾段正确编码标记；payload 只返回一个 span |
| 回绕进度 | 总空间与连续空间不足分别处理；独立发布 padding 后允许 `kFull`，消费端回收后大帧可重试；覆盖空队列非零位置 |
| 整数回绕 | 数据帧与 padding 跨 `UINT64_MAX` 后，累计位置、占用量和物理索引正确 |
| 复制适配 | 输出不足保留数据帧且不改输出，允许已回收前置 padding；重试不被借用标记阻塞 |
| 损坏状态 | 非法占用量、短 padding、环首回绕标记、越过尾部的帧及非法长度返回 `kCorrupt`，不消费数据帧 |
| 初始化与绑定 | 初始化失败不改区域；接入失败不改本地状态；未绑定及角色错误返回 `kInvalidState`；有借用解绑返回 `kBusy`，无借用重复解绑成功 |
| 外部内存 | 角色移交与回收遵守借用结束条件；视图与句柄不回收底层存储 |
| 共享映射 | 在 README 规定的验收平台，以不同映射地址验证帧序列与发布关系；借用地址仅在所属进程使用 |
| 性能 | 分别测量零拷贝控制、调用者载荷访问与复制便利接口成本，覆盖不同帧长及回绕比例 |
