# 策略定时事件

策略定时事件用于在没有新行情或交易回报时唤醒策略，驱动行情过期撤单和失败重试。定时器由 `StrategyRunner` 的主线程管理，不创建线程。

## 策略接口

每个策略实例拥有一个可替换的一次性定时器，通过 `context.timer()` 访问。公共接口位于 `yquant::strategy`：

```cpp
base::ErrorCode Arm(std::uint64_t deadline_ns) noexcept;
base::ErrorCode Cancel() noexcept;
std::optional<std::uint64_t> deadline() const noexcept;

base::ErrorCode Strategy::OnTimer(
    StrategyContext& context, const TimerEvent& event) noexcept;
```

`Arm()` 保存与 `context.Now()` 相同时间域中的绝对单调期限，替换之前的期限。零或过去的期限表示尽快派发，由主循环选择执行，不在调用栈内触发回调。`Cancel()` 清除尚未派发的期限，未设置定时器时也成功返回。`deadline()` 返回期限副本，空值表示未设置。

一次性通知 `TimerEvent` 包含：

| 字段 | 含义 |
| --- | --- |
| `deadline_ns` | 此次通知对应的预约期限 |
| `fire_time_ns` | 宿主选择派发时的单调时间，可能晚于期限 |

宿主在调用 `OnTimer()` 前清除该期限。因此进入回调时定时器为空，策略可以设置下一次通知；未重新设置则不再触发。`OnTimer()` 默认返回 `kOk`，不使用定时事件的策略可以不重写。

服务引用只在当前主线程回调期间借用。事件和查询结果可复制到策略存储，均不借用临时缓冲区。

## 生命周期

| 阶段 | 设置、取消 | 派发 |
| --- | --- | --- |
| `OnStart` | 允许 | 等全部启动步骤成功后才允许 |
| 正常运行的 `OnTick`、`OnOrderUpdate`、`OnFill`、`OnTimer` | 允许 | 由主循环串行派发 |
| 停止排空中的交易回调、`OnStop` | 返回 `kInvalidState` | 不再派发 |

接口仅供策略主线程在回调期间调用。未处于允许阶段的设置和取消返回 `kInvalidState`，保持原有期限不变。启动失败或进入停止阶段时，宿主立即清除期限。停止回调中的 `deadline()` 返回空值。

正常运行的 `OnTimer()` 与行情、交易业务回调具有相同的下单和撤单权限。定时器回调失败时，宿主保留首先发生的错误，关闭后续业务回调并继续能够完成的交易排空；已成功启动的策略仍配对一次 `OnStop()`。收尾规则见[交易执行设计](trading.md#错误与超时)。

## 主循环调度

定时器期限参与已有的最早期限选择：

```text
等待期限 = min(
    行情读取期限,
    行情冷维护期限,
    交易回报及本地请求期限,
    策略定时器期限,
    停止排空期限)
```

行情、交易和策略定时事件按持久轮转位置选择，共享每批最多 64 次处理额度。过期和重复来源事件仍占额度，定时器立即重新设置也占额度。每批结束后检查停止请求，单个持续就绪的来源不能阻止其他来源或停止检查。

行情源返回 `Idle` 后，本批不再读取行情，交易和定时事件可以继续使用剩余额度。定时事件不会插入同一成交回报的 `OnOrderUpdate()` 与 `OnFill()` 之间。

回调必须及时返回。期限不抢占正在执行的回调，`fire_time_ns` 用于表示实际派发时间。

## 实现与验证

`TimerImpl` 内嵌于 `StrategyRunner`，只保存一个可选期限及生命周期状态；`StrategyContextImpl` 借用该服务。设置、替换、取消、查询和消费均不申请或释放堆内存。公共接口变化按最新插件 ABI 同步重编译宿主及全部策略。

验证覆盖：

- 启动登记、期限替换、取消、过期立即触发、一次性消费和回调重新设置。
- 无行情时独立唤醒，三个事件来源之间的公平调度，以及停止清除期限。
- 定时回调内下单、撤单，回调失败后的交易排空和生命周期配对。
- 首次使用和重复操作的 C++ 堆活动检查。
